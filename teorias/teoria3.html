Codificación de la Información CLASE 4

Concepto General de Sistemas de Códigos

Si tenemos un alfabeto fuente \(S\) con símbolos \(\{S_1, S_2, ..., S_q\}\), se puede definir un **código** como la correspondencia de cada secuencia posible de \(S\) a una secuencia de símbolos en otro alfabeto \(X = \{x_1, x_2, ..., x_p\}\).

\(S\) recibe el nombre de **alfabeto fuente** y \(X\) el de **alfabeto código**. El número de símbolos de ambos conjuntos puede ser diferente.

Ejemplo de mapeo genérico: Con \(S = \{S_1, S_2, ..., S_5\}\) y \(X = \{x_1, x_2, ..., x_{10}\}\), una regla podría ser:

\(S_1 \rightarrow x_3 \quad | \quad S_2 S_4 S_5 \rightarrow x_1 x_2 x_8 x_5 \quad | \quad S_3 S_3 S_4 \rightarrow x_2 x_3 x_1\)

Esta definición es genérica y abarca tanto códigos útiles como inútiles. Un código será **útil** solo si es posible realizar el proceso inverso (decodificación).

Restricción Inicial: Códigos Bloque CLASE 4

Asignación Fija de Secuencias Lógicas

La primera restricción operacional consiste en obtener un **código bloque**: este asigna a cada símbolo \(S_i\) del alfabeto fuente una secuencia fija del alfabeto código, denominada **palabra código**.

Caso de Estudio (Código Ambigüo): Sea \(S = \{S_1, S_2, S_3, S_4\}\) y \(X = \{x_1, x_2, x_3\}\) con el siguiente esquema:

Símbolo Fuente Palabra Código
\(S_1\) \(x_3\)
\(S_2\) \(x_3 x_1\)
\(S_3\) \(x_1 x_2 x_3\)
\(S_4\) \(x_3 x_1\)

Este código bloque permite codificar, pero **no decodificar**, debido a que los símbolos distintos \(S_2\) y \(S_4\) comparten exactamente la misma palabra código.

Códigos No Singulares CLASE 4

Distinción Elemental de Palabras Código

Si exigimos que un código bloque tenga todas sus palabras código distintas para cada símbolo fuente individual, estamos en presencia de un **código no singular**.

A continuación se analizan dos esquemas de codificación de ejemplo:

Símbolo Esquema 1 (Binario)
\(S_1\) \(0\)
\(S_2\) \(11\)
\(S_3\) \(00\)
\(S_4\) \(01\)
Símbolo Esquema 2 (Ternario)
\(S_1\) \(x_3\)
\(S_2\) \(x_3 x_3\)
\(S_3\) \(x_1 x_2 x_1\)
\(S_4\) \(x_3 x_1\)

Nota Crítica: En el primer caso, si consideramos la secuencia binaria recibida `0011`, esta podría surgir de la combinación \(S_3 S_2\) o bien de \(S_1 S_1 S_2\). Esto demuestra que ser no singular **no es suficiente** para garantizar la decodificación.

Códigos Unívocamente Decodificables CLASE 4

No Singularidad Extendida de Orden n

Para que un código bloque se pueda decodificar con éxito, es preciso que sea no singular para cualquier **extensión de orden n**, siendo \(n\) un valor finito.

A este tipo de esquemas se los denomina **unívocamente decodificables**, lo que asegura que dos secuencias distintas de la fuente den lugar a tiras binarias de salida totalmente diferentes.

Análisis Comparativo de Longitudes CLASE 4

Códigos de Bloque de Tamaño Fijo y Variable

Que un código sea unívoco implica que es físicamente posible determinar el final de cada palabra dentro de una secuencia continua de símbolos.

Todo código bloque no singular cuyas palabras tengan exactamente la **misma longitud** será unívocamente decodificable de forma directa, aunque no es una condición obligatoria.

Símbolo Fuente Código A (Fijo) Código B (Coma) Código C (Variable Unívoco)
\(S_1\) \(00\) \(0\) \(0\)
\(S_2\) \(01\) \(10\) \(01\)
\(S_3\) \(10\) \(110\) \(011\)
\(S_4\) \(11\) \(1110\) \(0111\)

Los tres esquemas son no singulares y unívocos. El **Código A** es de longitud fija, el **Código B** es un código coma estándar, y el **Código C** es un esquema variable unívoco.

Códigos Instantáneos y Propiedad de Prefijo CLASE 4

Decodificación Sin Retardos Temporales

Se denomina **prefijo** de una palabra \(X_i = x_{i1} x_{i2} ... x_{im}\) a cualquier secuencia truncada inicial \((x_{i1}, x_{i2}, ..., x_{ij})\) donde \(j \le m\). Por ejemplo, la palabra `0111` tiene como prefijos a `0111`, `011`, `01` y `0`.

Un código unívocamente decodificable es **instantáneo** cuando permite recuperar las palabras de una secuencia sin precisar el conocimiento de los símbolos que las suceden en el tiempo.

Condición Necesaria y Suficiente:** Un código es instantáneo si y solo si **ninguna palabra coincide con el prefijo de otra**. La regla de diseño consiste en evitar la existencia de prefijos compartidos.

Símbolo Código A (No Instantáneo) Código B (Instantáneo) Código C (No Instantáneo)
\(S_1\) \(0\) \(00\) \(0\)
\(S_2\) \(01\) \(10\) \(01\)
\(S_3\) \(10\) \(110\) \(011\)
\(S_4\) \(11\) \(1110\) \(0111\)

La Inecuación de Kraft CLASE 5

Condición de Existencia para Códigos Instantáneos

Sea un alfabeto fuente \(S = \{S_1, S_2, ..., S_q\}\) y un alfabeto código \(X = \{x_1, x_2, ..., x_r\}\). Consideremos un código donde cada palabra posee una longitud \(l_i\).

Establecemos que es **condición suficiente** para la existencia de al menos un código instantáneo con dichas longitudes el cumplimiento de la **Inecuación de Kraft**:

\(\sum_{i=1}^{q} r^{-l_i} \le 1\)

Donde \(r\) representa el número de símbolos de \(X\). Para el caso del alfabeto binario, la inecuación se reduce a la expresión: \(\sum_{i=1}^{q} 2^{-l_i} \le 1\).

Limitación Teórica: Esta ley condiciona exclusivamente las longitudes de las palabras y no a las palabras en sí mismas. Es una medida cuantitativa; para asegurar que sea instantáneo se debe verificar la condición de prefijo.

La Inecuación de MacMillan CLASE 5

Extensión del Criterio para Códigos Unívocos

Como los códigos unívocamente decodificables incluyen formalmente a los instantáneos, MacMillan demostró que la inecuación de Kraft es **condición necesaria y suficiente** para la existencia de un código unívoco de esas longitudes. Por lo tanto, si el código es unívoco, necesariamente debe cumplir la inecuación de Kraft-MacMillan.

Ejemplo de Aplicación (Código Trinario): Supongamos una fuente de 10 símbolos que deseamos codificar con un alfabeto código trinario (\(r=3\)) utilizando las longitudes: \(1, 2, 2, 2, 2, 2, 3, 3, 3, 3\).

\(\sum_{i=1}^{10} 3^{-l_i} = 3^{-1} + 5 \cdot 3^{-2} + 4 \cdot 3^{-3} = \frac{1}{3} + \frac{5}{9} + \frac{4}{27} = \frac{28}{27} > 1\)

Como el resultado de la sumatoria es estrictamente mayor que 1, se demuestra que **no es posible** definir un código unívoco ni instantáneo bajo dicho ordenamiento.

Construcción de Códigos por Prefijos CLASE 5

Criterio de Optimización: Longitud Media \(L\) CLASE 5

Evaluación Métrica de Eficiencia en Bloques

Un aspecto central en la codificación es establecer un criterio matemático para seleccionar el código **óptimo**. Un código puede ser evaluado por comodidad, fiabilidad frente a errores, seguridad o costo.

En principio se adoptará la regla de **"cuanto más breve mejor"**, dado que la longitud de las palabras afecta de forma directa al almacenamiento en memoria y a la velocidad de transmisión.

Se define formalmente la **longitud media de un código (\(L\))** como el promedio de las longitudes de sus palabras ponderadas por sus probabilidades de ocurrencia en la fuente:

\(L = \sum_{i=1}^{q} P(S_i) \cdot l_i\)

Esta expresión fundamental del valor esperado es plenamente válida tanto para las fuentes discretas de memoria nula como para los procesos dependientes de Markov.

Teorema de la Codificación para Fuentes Nulas CLASE 5

El Límite Inferior de la Entropía Relativa

Un código bloque unívoco se define como **compacto** si su longitud media \(L\) es menor o igual que la longitud media de cualquier otro código unívoco aplicable a la fuente \(S\) usando el alfabeto \(X\).

A partir de las propiedades de la Entropía y la inecuación de Kraft, Shannon demuestra el teorema fundamental de la codificación lineal discreta:

\(H_r(S) \le L \quad \text{donde: } H_r(S) = \sum_{i=1}^{q} P(S_i) \log_r \left(\frac{1}{P(S_i)}\right)\)

La longitud media \(L\) de un código instantáneo posee un límite inferior absoluto determinado por la entropía en base \(r\). Alcanza su mínimo valor si y solo si las longitudes individuales cumplen:

\(l_i = \log_r \left(\frac{1}{P(S_i)}\right) \implies P(S_i) = \left(\frac{1}{r}\right)^{l_i}\)

Dado que las longitudes \(l_i\) deben ser enteros, esta condición de código compacto perfecto exige que todas las probabilidades de la fuente sean potencias enteras inversas de la base del alfabeto código.

Ejemplo de Distribución Compacta Perfecta CLASE 5

Resolución Numérica Binaria Equiprobable

Sea un alfabeto fuente \(S = \{S_1, S_2, S_3, S_4\}\) con distribución uniforme de probabilidades \(P = \{1/4, 1/4, 1/4, 1/4\}\). Calculamos la entropía binaria del sistema:

\(H_2(S) = \sum_{i=1}^{4} \frac{1}{4} \log_2(4) = 4 \cdot \left(\frac{1}{4} \cdot 2\right) = 2 \text{ bits/símbolo}\)

El teorema establece que es imposible codificar los símbolos de esta fuente mediante un código binario unívoco de longitud media inferior a 2 binits por símbolo.

Como el alfabeto código es binario (\(r=2\)) y la probabilidad de cada suceso es \(P(S_i) = 1/4\), se verifica el acoplamiento perfecto de la condición de potencia:

\(1/4 = (1/2)^2 \implies \alpha_i = 2 \quad \forall i\)

Puesto que el exponente resulta ser un entero exacto (\(\alpha_i = 2\)), el código compacto se construye utilizando palabras fijas de longitud 2: \(S_1 \rightarrow 00, S_2 \rightarrow 01, S_3 \rightarrow 10, S_4 \rightarrow 11\), logrando un rendimiento del 100% donde \(L = H_2(S) = 2\).
